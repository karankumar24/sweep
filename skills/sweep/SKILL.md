# Sweep

Script: `python3 -I "${CLAUDE_SKILL_DIR}/sweep.py"`. It is a dry run unless given `--apply`. `--selftest` runs its tests, `--explain <pid>...` explains a process and changes nothing, `--help` lists every flag.

macOS only. If `uname` is not Darwin, say so and stop. Moving files to the Trash (steps 6–8) needs `/usr/bin/trash`, which ships with macOS 15 and later; if it is missing, skip those steps and say why.

Heavy scans (storage, worktree bulk, session scratch, old transcripts) wait up to 30 s while the 1-minute load is at or above the number of CPU cores (at least 8), then skip. `--gentle` runs at the lowest CPU and IO priority. Delete only with `/usr/bin/trash` (the user empties the Trash), never `rm`. Never touch the Claude app's data folder or VM, Claude Code's installed versions, global Claude Code settings, or `~/.claude/projects/*/memory/`.

## Rules: prove it, or keep it and ask

These rules cover every run and every kind of leftover, including kinds not named here. Nothing is killed, cleared, archived or removed because of its name, a pattern or its age alone. Act only on what a command proved. Anything unproven, unchecked or not covered here is **kept**, listed with its evidence, and asked about with AskUserQuestion. The steps below only apply these rules.

- **A live owner means keep.** If anything up a process's parent chain is a Claude Code CLI or the Claude app, the process stays, whatever it runs. Dev servers whose parent is still running are listed under "Dev servers kept because their parent is running", with that parent.
- **A proven orphan** has all of these: it was reparented to launchd (ppid 1), the Claude session that started it (`CLAUDE_PID`, read with `ps -E`) has exited, lsof shows nothing outside its own tree connected to its ports, no process in its tree is working inside a live session's folder, no keep declaration covers it, and it is older than `--hours` (24 by default; a younger one is `ask owner`, with its age). Only proven orphans are killed by `--apply`.
- **Unproven means ask** (`ask owner`): no recorded owner, a live parent that is not Claude, a working directory inside a live session's folder, ports, clients or working directories that lsof could not check, or a kind sweep has no rule for (`unknown kind`).
- **Stopping something on a yes.** An `ask owner` tree or a kept dev server is stopped only after the user says yes in AskUserQuestion, with `--apply --kill <pid>`. Right before each signal the script re-checks every pid's parent, start time and command, and skips any that changed (pid reuse).
- **Codex job records** are marked failed only when they have been silent for 6 hours, their log shows no completed turn, and the Claude session recorded in them has exited, all re-checked right before writing. Anything else is `hung` and only reported.
- **Worktrees** are `removable` only when clean, every commit is on a remote, HEAD is merged into `origin/HEAD`, no process or live session is working in them, and no keep declaration or `.sweep-keep` covers them. Pushed but unmerged, or a repo with no `origin/HEAD`, is `ask`: keep it unless the user says to remove it.
- **Sessions** in the Claude app are archived only on the evidence in step 4.
- **Files** (worktree bulk, session scratch, transcripts) are only listed by the script. They go to the Trash or an archive only on the user's yes, and only if a fresh dry run right before acting still shows them unprotected. Session scratch is a `candidate` only when its session is not live, nothing in it or its transcript changed for 3+ days, and it holds no git repo, no process's working directory and no keep declaration. Transcripts are only `<uuid>.jsonl` files with their `<uuid>/` folders, and Codex `rollout-*.jsonl` files; every archived copy must match its unchanged original (size and sha256) before the originals go to the Trash.

## Steps

1. Run `python3 -I "${CLAUDE_SKILL_DIR}/sweep.py" --gentle` and show its summary. If it says heavy scans were skipped, finish the light steps and say so; don't loop waiting.
2. If `mcp__ccd_host__get_storage_usage` exists (the Claude desktop app), load it through ToolSearch and call it. Show one table: conversation history, worktrees, app scratch workspaces, session scratch, other Claude Code history, Codex sessions, app web cache, logs, free disk. Use the app's figures and fill the Codex and session-scratch rows from the script's Storage section. Without the tool, show the script's Storage section as it is.
3. Run `python3 -I "${CLAUDE_SKILL_DIR}/sweep.py" --apply --quick`. If the user typed the sweep command, that approves this step; it acts only where the rules prove it. If you started sweep on your own (the user only said something like "my disk is full"), first show the `would kill` list and ask with AskUserQuestion before running it. Never pass `--remove-worktrees` or `--transcripts` here. Then ask with AskUserQuestion (keeping is the default) about each `ask owner` tree (command, chain, evidence), each kept dev server whose session looks idle or gone (owner, age), and each `hung` Codex job (cancel it with `/codex:cancel <id>` only on a yes, if the Codex plugin is installed).
4. If `mcp__ccd_session_mgmt__list_sessions` exists, load it through ToolSearch and list up to 200 sessions. Archive with `mcp__ccd_session_mgmt__archive_session` only sessions whose `lastActivityAt` is more than 48 hours old, `isRunning` is false, not pinned, with no open PR (`prState` is not `OPEN`), and not the current session. Also skip sessions with a `branch` field (they own a worktree) and any session that started (`startedBy`) a session active in the last 48 hours. Archiving is reversible. If a field needed for a condition is missing or unclear, keep the session and list it. Report the count and titles. Without the tool, skip this step.
5. If the dry run found `removable` worktrees, ask with AskUserQuestion (multiSelect when there are several), with removal first as the recommended option. If the user approved every one, run `python3 -I "${CLAUDE_SKILL_DIR}/sweep.py" --apply --quick --remove-worktrees` (it removes all `removable` worktrees). If they approved only some, rerun the dry run and remove each approved one that is still `removable` with `git -C <repo> worktree remove <path>`. List `ask` worktrees with keep as the recommended option; remove one only on the user's explicit yes, with `git -C <repo> worktree remove <path>` (never `--force`).
6. Worktree bulk `candidate` rows (gitignored, untracked folders such as screenshots or build caches): if a live session is working in that checkout, first ask it (SendMessage) which folders it still needs. Then ask the user with AskUserQuestion (multiSelect, largest first, recommended = candidates unchanged for 3+ days). On a yes, rerun the dry run and trash only paths still `candidate`, with `/usr/bin/trash <path>`. `keep` rows are never offered. Say so in the option when a folder is a cache of downloads that would have to be fetched again.
7. Session scratch `candidate` rows: ask the user with AskUserQuestion (multiSelect, largest first). On a yes, rerun the dry run and trash only paths still `candidate`, with `/usr/bin/trash <path>`. `keep` and `list only` rows are never offered.
8. Old transcripts: if the dry run shows more than about 0.5 GB older than 7 days, ask with AskUserQuestion: archive (Recommended: one verified `.tgz` in `~/Archives/claude-chats` with an index, then the originals go to the Trash; chat logs compress only modestly, so expect a modest saving), trash without an archive, or skip. Also ask the age (7 days minimum; the script refuses less, and always skips live sessions, this session and memory folders). On a yes, rerun the dry run; if it still shows them, run `python3 -I "${CLAUDE_SKILL_DIR}/sweep.py" --apply --gentle --transcripts archive --days N` (or `--transcripts trash` if they chose no archive) in the background and report its `Transcript action` line.
9. Claude app actions, from step 2, only if those tools exist: if worktrees held by sessions belong to sessions inactive 30+ days, call `mcp__ccd_host__clean_up_worktrees` with `older_than_days` 30 (it shows its own approval card; never set `include_uncommitted` or `delete_sessions` unless the user asked). For each worktree kept after archive, ask with AskUserQuestion before `mcp__ccd_host__discard_kept_worktree` (it discards uncommitted changes). If the web cache is over 0.5 GB, tell the user where the app's Clear cache button is (Settings, Storage). Leave the app's kept-ready worktrees alone.
10. If `mcp__ccd_session_mgmt__get_usage` exists, call it. Above about 250k tokens in this session, recommend saving a handoff and starting a fresh session.
11. Show the script's settings recommendations. Ask before editing any settings.
12. Finish with a 3–5 line summary: trees killed, job records cleared, sessions archived, worktrees removed, GB trashed or archived (space returns when the Trash is emptied), free disk, and recommendations.

## Keep declarations

A session that needs something left alone writes `~/.claude/sweep/keep/<name>.txt` with lines like `port 5266`, `pid 1234` or `path /abs/folder`, or puts an empty `.sweep-keep` file in the folder. Sweep also keeps bulk folders changed in the last 24 hours, folders a process is working in, folders named in another live session's transcript, and anything git tracks. Declarations that no longer resolve (pid gone, nothing listening, path missing) are listed as `stale keep` for the user; sweep never edits keep files.
